# AngelHeart - 智能群聊/私聊交互插件

[![License: AGPL v3](https://img.shields.io/badge/License-AGPL_v3-blue.svg)](https://www.gnu.org/licenses/agpl-3.0)
[![AstrBot Plugin](https://img.shields.io/badge/AstrBot-Plugin-blue)](https://github.com/Soulter/AstrBot)

> 当前文档对应插件版本：`2.3.0`

AngelHeart 是一个专为 [AstrBot](https://github.com/Soulter/AstrBot) 平台设计的智能群聊/私聊交互插件。它采用**前台 / 秘书 / 助理**三角色协作与**两态群聊参与模型**，在需要时回复，在不该打扰时保持安静。

## 核心特性

### 三个角色

AngelHeart 不是“一个 AI 自己判断再自己说话”，而是三个各司其职的角色：

| 角色 | 职责 | 使用模型 |
|------|------|----------|
| **前台** | 整理消息、写入账本、调度入口 | 无（纯逻辑） |
| **秘书** | 巡检对话节奏、判断是否让助理接话 | 轻量模型 |
| **助理** | 实际生成回复内容 | 主模型 |

一条群聊消息的处理路径：

```text
收到消息 → 前台入账 → 秘书巡检 → 判断是否接话 → 助理生成回复
```

- **前台**不参与对话，只负责记账和调度。
- **秘书**用低成本模型做判断，快进快出；决定“不接话”就结束了，助理不会醒来。
- **助理**只在秘书放行后才生成高质量回复。

### 秘书的决策后端：轻量模型 / Jev 决策模型

秘书判断“该不该接话”可以用两种后端，在插件配置页的**秘书决策方式**里下拉选择：

| 方式 | 做什么 | 适合 |
|------|--------|------|
| `llm`（默认） | 轻量秘书模型读完整对话，产出完整决策（回复与否 + 策略 + 话题 + 实体） | 想要丰富上下文判断 |
| `jev` | 只用 [Jev 决策模型](https://jevmodel.org/zh/docs/) 做类型化判断，不调用大模型 | 只想要快、省 token |
| `hybrid` | 先用 Jev 廉价门控，通过后才调用秘书模型产出策略 | 兼顾成本与策略质量 |

Jev 是托管的**决策模型**：输入一段对话和一组类型化问题，返回 choice / score / noul 三种结构化答案，不生成文本。所以 Jev 路径能给出「要不要接话」「是否被追问」「话题有没有价值」「回复策略」，但给不出话题、实体、事实这些自由文本（话题用最新一条消息近似）。

- **只对输入 token 计费**，输出免费；单次调用通常 2–4 秒。
- 两个网关请求体完全一致，切换只需改接口地址并换上对应网关的 Key：默认 `https://jevmodel.org`（控制台自助创建 `sk-` 开头的 Key，登录即送 10 万免费输入 token），也可换成 `https://api.typesafe.ai`。
- **概率怎么用**：Jev 的 noul 答案就是「该接话」的概率。插件有两种口径，在**Jev 决策**分组里用「概率判定方式」下拉切换：
  - `sample`（默认）：按概率抽样接话，回复率随置信度**平滑**变化——0.3 的消息有 30% 机会接话，0.9 的有 90%，没有阈值处的跳变；
  - `threshold`：概率超过阈值才接话，行为可复现、便于复盘，但阈值附近是硬跳变（0.59 不接、0.61 就接）。
  - 两种口径下「非提问也回复」「被追问 / 有兴趣」这两道证据门都照旧生效。
- **概率也管「说多少」**：Jev 路径下把握越小，允许的回复字数越少（置信度 0 → 半数额度，1 → 全额）；把握不足 0.5 时还会额外提示一句「只说最关键的一句」。
- 开关与参数在插件配置页的**Jev 决策**分组：`enabled` 总开关、`api_key`、`base_url`、`api_format`、`model`、`timeout_sec`、`retries`、`reply_mode` 与三个概率阈值。
- **接口协议可切换**：`api_format` 选 `systemone`（默认，POST `/v1/systemone`，官方 Jev / TypeSafe / StartLux 走这个）或 `decisions`（POST `/v1/decisions`，OpenAI Decisions 协议，部分中转站用这个端点）。两者请求体结构不同，插件内部自动翻译，判定逻辑不变。
- Jev 判定为「不回复」或调用失败时，本轮降级为不接话，不影响群聊。

细节见 [docs/architecture/jev_decision_backend.md](docs/architecture/jev_decision_backend.md)。

### 两态群聊参与模型

群聊只有“离场”和“在场”两种参与状态：

- **离场 (NOT_PRESENT)**：只记录消息，不主动加入聊天。默认只有被 @ 或命中点名词才会进场；若开启离场应答，复读或密集聊天可以得到一次回复，但回复后仍保持离场。
- **在场 (OBSERVATION)**：被点名时进入，在回复后继续保持。群聊暂时安静后，才由秘书判断是否需要接话；在场时间超过上限后，收到下一条消息时回到离场。

点名和普通群聊消息分别使用不同的等待规则；旧事件会被新的边界消息替换，避免针对半句话作答。

### 巡检：秘书的调度机制

秘书不是每条消息都去判断。它有自己的节奏——这就是**巡检**。

- **点名巡检**：有人 @ 助理或叫到助理时，前台会先等待一段补充消息时间，再交给秘书判断。
- **普通巡检**：助理已在参与群聊时，等群聊暂时安静下来，秘书才开始判断要不要接话。
- **边界替换**：等待期间的新消息会替换旧边界事件，只有最后一条消息能触发秘书判断。
- **同会话单飞**：同一群聊同时只允许一轮秘书判断在跑；秘书把事件交给助理后立即释放，不占用助理生成和发送阶段。
- **普通巡检抑制**：助理被调用后会进入休息，期间普通消息不会立刻触发新巡检。
- **点名升级**：普通巡检等待期间有人叫到助理，当前巡检升级为点名巡检，不会创建第二套调度。

### 能量：助理也会累

助理不是不知疲倦的。话说多了会累，**长发言比短发言更消耗精力**，所以长回复后的发言频率自然会降下来。

- 刚上线时精力充沛，聊什么都有劲。
- 说一次话会消耗一部分精力；发言越长，消耗越多。
- 累了就先歇着，等精力恢复一些，再由秘书判断要不要接话。
- 如果有人直接点名助理，点名会进入对应防抖；到期放行仍受助理忙碌和休息门闩约束，但不受精力门槛限制。

具体规则：

- 每次秘书普通巡检前，会按**经过的时间**自动恢复一点精力，不会超过上限。
- 精力够，秘书才进入判断；精力不够，保留巡检记录并重新计时，等恢复后再判断。
- **点名巡检**和**离场一次性应答**不受精力限制；点名仍会检查助理忙碌和休息门闩。
- 助理发出回复后，按实际内容消耗精力：

```text
消耗 = 基础消耗（默认 14） + 有效字符数 × 每字符消耗（默认 0.12）
```

短回复耗能少、恢复快，可以更频繁接话；长回复耗能多，说完需要更长时间恢复。扣到下限后不再继续扣，不会把助理卡死。

默认数值：

| 参数 | 默认值 | 含义 |
|------|--------|------|
| 初始精力 / 上限 | 100 | 一开始精力充沛，恢复也不超过此值 |
| 精力下限 | -100 | 扣到底后不再继续扣 |
| 每秒恢复 | 0.6 | 大约 3 分钟从空恢复到满 |
| 回复基础消耗 | 14 | 每次开口的基础代价 |
| 每字符消耗 | 0.12 | 说得越多越累 |

精力按群独立保存在内存中，插件重启后回到初始值。`[能量设置]` 分组可调整全部参数；修改后新巡检立即生效，已有群的当前精力不重置。

### 群聊独立配置与联系人监控

不同群可以绑定不同配置模板：人设、唤醒词、回复长度、能量、回复节奏都可以按群定制。未绑定的群继续使用全局配置。

插件页面提供「联系人监控」视图，实时查看每个群或私聊的运行状态：

- 当前是在场还是离场
- 剩余能量
- 巡检 / 等待进度
- 最近一次是否决定回复及原因

状态每 3 秒自动刷新。字段说明以插件 WebUI 和 `_conf_schema.json` 为准。

### 上下文与图片

- **群聊上下文接管**：把完整对话历史格式化后再交给助理，发言人、时间戳和内容不会混在一起。
- **私聊上下文接管**：私聊消息也会写入插件内部账本；私聊仍由主框架直接回复，不走秘书判定。
- **按需图片理解**：主模型需要某张图的细节时，再调用 `angel_describe_image`；当前轮支持图片时走 AstrBot 原生图片链路。

同一只粉毛天使的五个能力化身：

| 插件 | 能力 |
|------|------|

### 支持哪些网关

| 网关 | 接口地址 | 端点路径 | 接口协议 | Key |
|---|---|---|---|---|
| Jev 官方 | `https://jevmodel.org` | `/v1/systemone` | systemone | `sk-` 开头 |
| TypeSafe | `https://api.typesafe.ai` | `/v1/systemone` | systemone | `sk-` 开头 |
| JevTypeSafeAI（第三方代理） | `https://jevtypesafeai.com` | `/api/v1/decide` | systemone | `jv_live_` 开头 |

第三方代理的协议与官方一致，只是路径带 `/api` 前缀——把「端点路径」填成
`/api/v1/decide` 即可。其余网关留空「端点路径」，插件会按「接口协议」自动拼。

不确定配置对不对时，跑一下 `python scripts/probe_jev.py --base-url ... --api-key ...`，
它会告诉你问题出在 Key、余额、路径、模型通道还是上游。

## 快速开始

### 前置要求

- [AstrBot](https://github.com/Soulter/AstrBot) 平台已安装并运行
- Python 3.10+ 环境
- 至少一个可用的 AI 模型提供商

### 安装步骤

1. **市场安装**
   - 在 AstrBot 的 插件-插件市场中搜索「天使之心」安装

2. **非市场安装**
   - 将插件克隆或下载到 AstrBot 的 plugins 目录

安装后在插件配置里指定秘书模型（`analyzer_model`），并按需要打开群聊上下文接管。详细机制见 [docs/angelheart_workflow.md](docs/angelheart_workflow.md)。

想让秘书改用 Jev 决策模型，就把「秘书决策方式」切到 `jev` 或 `hybrid`，并在「Jev 决策」分组里填好接口地址与 API Key；不填也能用，切回 `llm` 即可回到原来的行为。
